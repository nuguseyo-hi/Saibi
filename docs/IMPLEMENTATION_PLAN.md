# 단계별 개발 계획

현재는 사용자 후속 요청에 따라 **프로젝트 초기화와 타이틀·대화·JSON 선택지 분기**를 구현했다. 아래는 전체 게임의 단계별 계획이며 모든 단계가 완료된 것은 아니다. 고해성사 전용 기능, 사고 편집, 수치 변화와 저장은 이후 범위다. 실행 방법과 현재 검수 절차는 루트 README.md를 참고한다. 소요 기간은 일정과 리소스가 정해지지 않아 산정하지 않는다.

참조: [게임 기획](GAME_DESIGN.md), [기술·데이터 계약](TECH_STACK.md), [개발 규칙](../AGENTS.md).

## 0단계 — 요구사항과 설계 정리

산출물은 위 세 문서와 루트 AGENTS.md다. 확정 요구사항과 제안·미정 사항을 구분하고 콘텐츠·상태·UI의 경계를 정한다.

완료 기준:

- 네 문서가 존재하며 서로 연결된다.
- 폴더, 컴포넌트, 상태, 대화·편집 데이터, JSON 예시, 단계별 완료 기준을 포함한다.
- 예시 JSON이 파싱되며 ID 참조와 두 편집 경로가 문서상 일관된다.
- 실제 게임 코드·설정·의존성 파일을 생성하지 않는다.

## 1단계 — 프로젝트 기반과 데이터 계약

구현 요청을 받은 뒤 기존 파일을 다시 확인한다. React·TypeScript·Vite, Tailwind CSS, Zustand를 설정하고 기술 문서의 폴더 경계를 만든다. 데이터 타입과 검증기, 플레이스홀더 에셋, manifest를 도입한다. 빈 디렉터리를 미래 확장만을 위해 과도하게 만들지 않는다.

착수 전 결정: 패키지 버전과 매니저, 상태 범위·초기값, 첫 캐릭터 및 임시 콘텐츠 사용 여부.

완료 기준:

- 개발 서버와 프로덕션 빌드가 성공하고 TypeScript 검사에 오류가 없다.
- 배경·캐릭터 플레이스홀더와 16:9 기본 화면이 나타난다.
- 정상 JSON을 읽고 중복 ID·누락된 참조·잘못된 타입은 명확한 에러로 거부한다.
- 콘텐츠 원본, domain, UI가 독립된 모듈이다.

## 2단계 — 캐릭터 상태와 공통 규칙

캐릭터 정의에서 실행 상태를 생성하고 Zustand 액션, 조건 평가, 효과 적용을 연결한다. stats, flags, events, route, editHistory, seenEndingIds를 관리한다. 이후 시스템이 재사용할 진행 상태 전이를 정의한다.

완료 기준:

- 캐릭터 ID별 상태가 분리되어 있고 원본 JSON은 변하지 않는다.
- 네 수치의 증감·경계값과 flag, AND/OR/NOT 조건이 결정된 규칙대로 계산된다.
- 효과를 UI 렌더링에서 실행하지 않는다.
- 잘못된 캐릭터·키·비유한 숫자를 거부한다.
- 조건·효과·범위 제한의 핵심 동작을 자동 검증한다. 실제 캐릭터 콘텐츠는 한 명만 작성한다.

## 3단계 — 대화와 고해성사

타이틀, 교회, 고해성사 화면과 대사·화자·선택지·로그를 연결한다. next, 조건부 선택, branch, 기본 경로와 ending을 해석한다. 실제 콘텐츠는 JSON에서 제공한다.

착수 전 결정: 분기 충돌 우선순위, 임시 엔딩과 대사.

완료 기준:

- 게임 시작부터 고해성사까지 진행할 수 있다.
- 상태에 따라 선택지·대사 분기가 바뀌고 선택 결과가 저장소 상태에 반영된다.
- 로그는 당시 출력된 대사와 선택을 순서대로 보존한다.
- 조건을 만족하는 선택지가 하나도 없는 상태에서 무한 대기하지 않는다.
- 잘못된 next 참조와 자동 분기 순환을 감지한다.
- 재렌더링·연속 입력·노드 재방문의 효과 적용 정책을 검증한다.

## 4단계 — 사고 편집

텍스트 세그먼트와 편집 영역 표시, 삭제, 치환 옵션, 미리보기, 확정 기능을 구현한다. 확정 전 초안과 확정된 캐릭터 상태를 구분한다.

착수 전 결정: 세션당 편집 건수, 무편집 진행, 취소·이탈·되돌리기, 비용·실패 규칙. 합의 전 해당 정책을 조용히 고정하지 않는다.

완료 기준:

- 정의된 영역에만 삭제·치환을 수행할 수 있고 자유 텍스트 입력이 없다.
- 선택을 바꾸는 동안 stats·flags·editHistory가 변하지 않는다.
- 확정 시 정의된 효과와 플래그, 전후 문장, 편집 기록이 함께 반영된다.
- 더블 클릭과 동일 세션 재확정으로 효과가 중복 적용되지 않는다.
- 금지 연산, 알 수 없는 영역·대체어를 거부한다.
- 두 연산과 무효 입력, 초안 변경, 중복 확정 방지에 대한 핵심 검증이 통과한다.

## 5단계 — 결과·후속 대화·엔딩 연결

결과 화면에 확정된 텍스트를 표시하고 이전 고해성사 시나리오의 복귀 노드로 연결한다. 기억 플래그와 수치가 이후 대화·결말에 영향을 주도록 구성한다.

착수 전 결정: 수치 변화 공개 범위, 최종 프로토타입 대사와 엔딩 조건.

완료 기준:

- 새 게임 → 등장 → 대화 → 고해성사 → 편집 → 확정 → 결과 → 후속 대화 → 엔딩을 완주한다.
- 새 게임에서 각각 삭제와 치환을 선택하면 서로 다른 후속 대사·임시 엔딩을 확인한다.
- 엔딩 ID, 이벤트 완료, 루트 완료 정보가 해당 캐릭터 상태에 남는다.
- 결과 화면을 반복 렌더링하거나 후속 대화로 이동해도 효과를 다시 적용하지 않는다.
- 같은 타입의 대사·편집 옵션을 JSON 수정으로 추가할 수 있다.

## 6단계 — 저장·복원과 오류 처리

버전 envelope, 자동 저장·이어하기, 오류 안내를 구현한다. 단일 슬롯과 초안 비저장은 제안이며 구현 전에 확정한다.

완료 기준:

- 대화·선택 이후 새로고침 시 위치·상태·로그가 복원된다.
- 편집 초안의 저장 여부가 정해진 정책과 일치한다.
- 결과 화면에서 새로고침해도 효과·기록이 중복되지 않고 다음 대화로 갈 수 있다.
- 엔딩 이후 복원도 정확하다.
- 손상 JSON, 미지원 버전, 사라진 노드 참조를 감지하고 기존 원본을 조용히 덮어쓰지 않는다.
- localStorage 접근 실패·용량 초과를 사용자에게 알리고 메모리 내 플레이를 유지한다.
- 새 게임이 이전 캐릭터 상태를 재사용하지 않는다.
- 상태 저장/복원 왕복과 중복 효과 방지 검증을 통과한다.

## 7단계 — PC UI 검수와 프로토타입 전달

고딕 색상·글꼴·프레임과 사고 편집 진입 연출을 정리한다. 실제 일러스트 제작과 모바일 완성은 포함하지 않는다.

완료 기준:

- 기준 PC 해상도 제안인 1280×720, 1920×1080에서 대사와 선택지가 잘리지 않는다.
- 16:9가 아닌 창에서도 중요 입력이 화면 밖으로 사라지지 않는다.
- 키보드 포커스와 선택·확정 동작, 로그 열기·닫기를 확인한다.
- 연출이 읽기나 조작을 방해하지 않는다. 연출 감소 지원 여부를 결정해 검수한다.
- 합의한 브라우저에서 두 편집 경로와 이어하기를 실제 확인한다. 초기 제안은 Chrome·Firefox 최신 안정판이다.
- 빌드·타입 검사·핵심 자동 검증이 통과하고 콘솔 오류와 에셋 로드 실패가 없다.
- 실행 명령, 브라우저 테스트 결과, 제한사항을 전달한다.

## 향후 브라우저 테스트 절차

다음 명령은 **구현 단계에서 npm을 채택하고 해당 scripts를 추가했을 때** 사용할 예정이며 지금 실행할 수 있는 앱은 없다.

```sh
npm ci
npm run dev
npm run typecheck
npm run test
npm run build
npm run preview
```

개발 서버 또는 preview가 출력한 로컬 URL을 연다. 포트를 고정 추정하지 않는다. localStorage는 origin 단위이므로 개발 서버와 preview의 포트가 다르면 세이브가 공유되지 않을 수 있다.

| 검수 | 조작 | 기대 결과 |
| --- | --- | --- |
| 치환 경로 | 새 게임 → '천천히 말해 보세요' → 나의/운명의 치환 → 확정 | 예시 수치 12/10/15/0, blameShifted=true, 운명의 이름 엔딩 |
| 삭제 경로 | 새 게임 → 같은 선택 → 영역 삭제 → 확정 | 예시 수치 12/0/10/10, blameErased=true, 비어 버린 주어 엔딩 |
| 초안 변경 | 치환 선택 후 삭제로 변경, 확정 전 상태 확인 | 초안만 바뀌고 실제 상태·기록 불변 |
| 중복 입력 | 확정 버튼 빠르게 두 번 입력 | 이력 한 건, 효과 한 번 |
| 대화 복원 | 대화 중 새로고침 | 같은 진행 상태, 과거 효과 재적용 없음 |
| 편집 복원 | 초안 상태에서 새로고침 | 제안 정책 채택 시 같은 세션 원문으로 복귀 |
| 결과 복원 | 확정 후 결과 화면에서 새로고침 | 결과 유지, 이력 한 건, 후속 분기 일치 |
| 손상 세이브 | 테스트용 세이브 백업 후 대상 키에 깨진 JSON 입력 | 오류 안내, 자동 덮어쓰기 없음 |
| 비호환 세이브 | 테스트용 schemaVersion 또는 nodeId 변경 | 이어하기 차단, 이유 표시 |
| 저장 실패 | 테스트용 저장 어댑터에서 예외 주입 | 플레이 지속, 저장 실패 표시 |
| 새 게임 | 진행 후 새 게임 | 초기 상태, 이전 로그·기억 유입 없음 |

수치는 기술 문서의 임시 콘텐츠를 채택할 경우의 기대값이다. DevTools에서 세이브를 조작할 때 전체 localStorage를 지우지 않고 해당 게임의 테스트 키만 사용한다. 브라우저 테스트를 실제 수행하지 못했다면 통과했다고 보고하지 않는다.

## 이후 확장 — 현재 구현 범위 아님

검증된 프로토타입을 기준으로 두 번째 캐릭터, 반복 방문과 장기 개인 루트, 추가 편집 연산, 여러 저장 슬롯, 반응형 UI를 각각 별도 단계로 계획한다. 캐릭터 간 영향·일정 관리·교단 경영은 현재 요구 범위에 자동 포함하지 않는다.
