# 최초의 사도 — 프롤로그 구현 계약

사용자 기획 원문은 [PROLOGUE_BRIEF.md](PROLOGUE_BRIEF.md)다. 태양신과 니알라토텝은 서로 다른 존재다. 금발 인물은 원래 태양신의 이단심문관이며, 프롤로그에서 정체성을 바꾼 뒤 플레이어가 조작하는 최초의 사도가 된다. 검은 로브는 프롤로그의 임시 역할이며 정체를 밝히지 않는다. 태양신이 밤에 응답하지 않는다는 말은 인물/나레이터의 주장이고 세계의 확정 규칙으로 구현하지 않았다.

## 기존 코드 분석과 통합

기존에는 대화·선택지, 에밀리아 고해성사, 경계도 테스트값, Phaser 이동/충돌/문자 적, 기존 사고 편집과 저장이 있었다. 인형극, 키워드 수집, 텍스트 지형, 정체성 전환, 낮 조사 화면은 없었다. 따라서 기존 코드를 지우거나 프로젝트를 다시 만들지 않고 프롤로그 기능을 추가했다.

- `parseScenario`, `getDialogue`, `getNextNode`와 `ChoiceList`, `DialogueBox`, `DialogueLog` 재사용.
- 최종 사고는 기존 `parseMindEvents` / `commitDraft` / `MindEditScreen` 재사용.
- `DungeonScene`의 이동·카메라·충돌·기존 문자 적·리소스 생명주기 재사용. 선택적인 확장 콜백으로 텍스트 지형을 연결.
- 이전 `App`을 보존하고 새 프롤로그 진입점에서 불러온다. 타이틀에서 기존 에밀리아 저장을 이어갈 수 있다.
- 프롤로그는 별도의 버전 저장 키를 사용해 기존 저장과 캐릭터 ID를 변경하지 않는다.

## 상태와 저장

키 `saibi.prologue.v1`, 저장 version 1, 콘텐츠 `first-act-1`. 기존 `nyarlathotep-vn.save.v1`은 그대로 둔다. 서버나 계정 저장은 추가하지 않았다.

프롤로그 상태는 phase(story/dungeon/core/village/church), nodeId, guard, questions, keywords, environment, dungeon, events, editResult, resistance, name, playableId, completed, rejectedNode, doorOpensAt, cue, sealFlipped, sealAttempted, log, visited, revision이다.

- 초기 guard90 → 응답에서100 → 강제 편집 노드에서0. 상태 변화는 버튼 action에서 반영하며 애니메이션 끝에 의존하지 않는다.
- 질문은 순서 자유·재질문 가능. 세 질문을 모두 선택하고 답변을 확인하면 다음 단계로 갈 수 있다.
- 대사 키워드는 구간 ID와 keywordId로 처리한다. 중복 수집은 무시한다. 첫 구역의 ‘접힌 대화의 기억’에서 놓친 다섯 키워드를 모두 복구할 수 있다.
- 환경 편집 초안은 React 로컬 상태이며 저장하지 않는다. TextWorld에만 미리보기를 전달한다. 취소/타이틀 이탈/새로고침은 확정 상태로 돌아간다.
- 문 열림 타이머는 절대시각으로 저장한다. 페이지를 닫은 동안에도 시간이 흐른다.
- 최종 결과는 세션 `first-identity`로 한 번만 확정한다. 사명 문장은 그대로 남고 첫 문장은 ‘나는 ■■■■■■■의 사도다.’로 바뀐다.
- 이름은 앞뒤 공백을 제거한 1~20자 일반 문자열이다. 제어문자는 거부하고 HTML로 해석하지 않는다.
- 이름 입력 뒤 역할 전환 노드에서 playableId를 vessel → inquisitor로 바꾸고 completed를 저장한다.
- 손상/비호환 저장은 자동 덮어쓰지 않는다. 새 공연의 명시적 확인으로만 교체한다. 저장 실패는 안내와 재시도를 제공한다.

## 텍스트와 환경 규칙

문자열 내용으로 게임 조건을 비교하지 않는다. rule ID, option ID, result ID와 stateKey/value를 이용한다.

| 규칙 | 상태 | 실제 영향 |
| --- | --- | --- |
| wall_rule | solid / crossed | ‘절대로’의 굵은 몸체 / 취소선·충돌 해제 |
| bridge_rule | folded / open | ‘동료’ 키워드 삽입 시 구멍을 가리던 몸체 제거, 밑줄 종이 다리 펼침 |
| punctuation_rule | exclaim / question | ‘싫어!’ 돌진 / ‘싫어?’ 잠시 망설인 뒤 느린 배회 |
| denial_rule | attached / detached | ‘아니야’가 붙은 장애물 / 분리 후 통행 |
| door_rule | closed / waiting / open | 문 충돌 유지 / 4초 대기 / 즉시 해제 |
| order_rule | original / swapped | 첫 두 사고의 표시 위치·조명·인형 배치 변경, 최종 결과는 고정 |

텍스트의 style과 collider는 같은 `textPhysics` 결과를 사용한다. 밑줄의 길 양옆은 여전히 충돌하므로 다리가 실제 통행로가 된다. 괄호 영역 안에서는 종이 색이 바뀐다. 신념을 수정하려 하면 identity=resisting/저항1로 바뀌며 벽과 움직이는 저항 문자가 나타난다. 나레이터의 도움으로 저항0/unsealed가 되고 최종 기존 편집 UI가 열린다.

Phaser의 프레임 좌표는 내부에만 보유한다. React 콜백으로 조사·피격·이동·확정 같은 의미 있는 이벤트만 저장한다. 별도 DOM 커스텀 이벤트 리스너를 늘리지 않는다. 동적 import 해제 가드와 Game destroy, 창 이벤트 정리는 기존 패턴을 재사용했다. 모달과 포커스 이탈에서는 이동·적을 멈춘다. 새로고침 시 월드 상태를 다시 계산하며 확정 이벤트를 재실행하지 않는다.

## 직접 플레이 및 퍼즐 확인

1. 타이틀에서 ‘막을 올리다’. ‘아니요’를 고르면 강제 긍정으로 바뀐다. ‘네’도 같은 다음 장면에 도착한다.
2. 폐허에서 어느 답을 골라도 경계도90→100, 손의 개입에서0이 된다.
3. 세 질문을 순서 자유로 진행하고 밑줄 단어를 클릭한다. 질문을 마친 뒤 금발 인물에 마우스를 올리고 클릭한다.
4. 이동 WASD/방향키, 조사 E, 일시정지 Escape. 조작되지 않으면 캔버스를 클릭한다.
5. 배신의 회랑: ‘단단한 글자’에서 굵은/취소선 미리보기와 취소·확정을 비교한다. ‘거짓’ 취소선은 통과된다. ‘거부의 문장부호’를 물음표로 바꾸고 적을 확인한다.
6. ‘믿음의 다리’에 동료를 삽입한다. 키워드가 없으면 입구 아래의 접힌 대화를 조사한다. 열린 밑줄 다리를 건너 오른쪽 인형의 기억을 확인한 후 다음 장면으로 간다.
7. 예배당: 처음 금빛 신념은 편집 불가다. ‘붙어 있는 부정’을 분리하고 문장을 ‘이미 열려 있다’ 또는 ‘잠시 후 열린다’로 확정한다. 취소 시 충돌 복원이 되는지도 확인한다.
8. 안쪽 제단에서 편집을 시도하고 종이를 뒤집어 숨은 문장을 본다. 도움을 요청하고 나레이터 대사를 진행하면 봉인이 찢어지고 뒤의 공간과 출구가 열린다.
9. 이름 없는 제단: 사고 순서를 바꿔 조명·문장·인형 위치를 비교한다. 믿음의 대상을 키워드로 바꾸려 하면 자아가 저항한다. 나레이터 개입 후 ‘가려진 이름의 사도’를 확정한다. 취소하면 제단으로 돌아가 재진입할 수 있다.
10. 붕괴 후 폐허에서 이름을 입력한다. 금발 인물이 플레이어로 바뀌고 제1장 세루스의 낮 조사로 넘어간다.
11. 세루스 세 장소를 조사한 뒤 밤의 교회로 들어가면 기존 에밀리아 테스트가 실행된다. 상단/하단 복귀 버튼으로 세루스로 돌아온다.
12. 각 단계에서 새로고침, 던전 재진입, 문자 편집 취소, 빠른 중복 클릭, 연출 약하게 옵션을 확인한다.

## 검증과 남은 범위

자동 테스트 45개(기존34 + 프롤로그11): 네 대화 조합 전체 진행, 키워드 누락 복구/중복 방지, 굵은/취소선/밑줄 규칙, 미확정 취소, 지연 문 복원, 같은 효과 중복 방지, 필수 이벤트 스킵 방지, 무적/안정도/재시도, 핵심 편집 취소·확정·복원, 이름·역할 전환, 기존 저장 보존, 손상 저장/쓰기 오류, 에셋 경로, 전체 구역의 통행 가능한 접근 경로를 검사한다. TypeScript와 Vite 빌드도 실행한다.

현재 채팅에는 브라우저 제어 도구가 없어 실제 키보드 조작, Canvas 중복 생성 여부, 시각 배치·전환 타이밍을 브라우저로 검수하지 못했다. 위 자동 테스트는 상태와 순수 규칙 검증이며 실제 브라우저 E2E 테스트라는 뜻이 아니다. 완성 일러스트 대신 요청대로 임시 SVG와 기존 콜라주를 사용했다. 실제 음원, 완전한 낮/밤 일정 시스템, 추가 주민 조사·분기, 완성된 본편은 범위 밖이다. 세루스는 연결을 위한 최소 조사 화면이다. 10~15분 플레이 시간은 목표이며 실측하지 않았다.
